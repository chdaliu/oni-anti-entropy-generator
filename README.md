# 反熵发电机（ONI-Anti-Entropy-Generator）

> 英文 Mod 名 / 程序集：`AntiEntropyGenerator`（不带 `ONI-` 前缀；文件夹名按需求使用 `ONI-Anti-Entropy-Generator`）。

《缺氧》Mod：新增一台 **4x3** 的反熵发电机。它接收液体和气体，冷却后从对应管道输出，并把从介质中移除的热量转化为电力；同时按液体/气体散热器的功率消耗电力、按散热器的热量发热。

## 建筑

- **尺寸**：宽 4、高 3。
- **建造材料**：精炼金属（钢、铜、铁、铌、导热质等），1200 kg。
- **建造位置**：电力 → 发电机。
- **科技**：与蒸汽涡轮机同一组，`RenewableEnergy`（在蒸汽发电机那一组研究完成后解锁）。
- **不可损坏**：不会被破坏、熔化、淹没或过热损坏；只能通过“拆除”指令移除。
- **停止条件**：建筑温度达到建造材料的过热温度后停止工作，冷却后自动恢复；过热时不会受到伤害。
- **需要接电**：电力输出口没有接入电网时不会运行（输入/输出管道仍可通行，但不会冷却）。
- **双向电力口**：同一个电力接口既向外输出净发电量，也会在发电量不足时从电网取电补足散热器耗电；电网无法补足差额时机器会停机，直到电网恢复供电。

## 接口

一共 5 个接口，全部在建筑占地范围内：

| 接口 | 相对建筑原点偏移 | 位置 |
| --- | --- | --- |
| 液体输入 | `(-1, 0)` | 左下 |
| 液体输出 | `(2, 0)` | 右下 |
| 气体输入 | `(-1, 2)` | 左上 |
| 气体输出 | `(2, 2)` | 右上 |
| 电力（输出/取电） | `(0, 0)` | 底排中间 |

> 4 格宽建筑的 `PlacementOffsets` 是 `-1..2`，建筑原点在底排从左数第二格。因此左右接口必须使用 `-1` 和 `2`，而不是 `0` 和 `3`；否则接口会整体偏移一格。

液体/气体接口都是 secondary conduit，因此同一栋建筑可以同时拥有液体和气体输入/输出。电力只有一个双向接口：净发电时向外送电，发电不足时从同一根电线取电。

## 工作机制

每 200 ms 处理一次，液体最多 10 kg/s，气体最多 1 kg/s。

1. **最低温度（温度下限）**
   - 侧边栏滑块，范围 0 K–10000 K（约 -273°C–9727°C），默认 20°C。
   - 这是温度**下限**，不是温度上限：传入介质高于它时会继续冷却；等于或低于它时才跳过冷却。
   - 冷却不会把介质降到这个温度以下。
   - 单次经过的温降为 `min(14°C × 倍率, 介质温度 - 最低温度)`；最低温度是地板，机器不会越过它。单级管道每次只降低有限温度，需要循环或多级管道才能接近地板。
   - 对蒸汽等易凝结气体、或易冻结液体，请把最低温度设在其相变温度以上，避免输出管道内发生相变堵塞。

2. **降温倍率**
   - 侧边栏滑块，范围 0–300%，默认 100%。
   - 同时缩放：降温幅度、散热器耗电、散热器发热、由移除热量产生的电力。
   - 100% 对应标准工况：液体 ΔT 14°C、气体 ΔT 14°C。

3. **冷却**
   - `实际 ΔT = min(14°C × 倍率, 介质温度 - 最低温度)`。
   - `移除热量 Q = 质量 × 比热容 × 实际 ΔT`。
   - 冷却后的介质进入输出缓冲，再由输出管道送出。

4. **发电**
   - 每种介质各自贡献最多 2000 W；两种都接入时合计上限 4000 W。
   - 贡献比例 = `Q / (额定流量 × 该元素比热容 × 14°C)`。
   - 也就是说，满流量、满 14°C 温差时，液体或气体各自贡献 2000 W。
   - 总发电受 4000 W 上限限制。

5. **耗电**
   - 液体散热器：1200 W × 液体流量比例。
   - 气体散热器：240 W × 气体流量比例（实际处理质量 / 额定流量）。
   - 耗电跟随实际处理量；发电跟随实际移除热量。介质接近最低温度时温差很小，发电会下降，但散热器仍按流量耗电，因此可能出现耗电大于发电。

6. **净输出 / 电网取电**
   - `总发电 - 散热器耗电` 为正时，差额作为净输出送入电网。
   - 为负时，差额从电网（电池或其他发电机）取电补足。
   - 电网无法补足差额时，机器会停机，避免无电冷却；电网恢复后自动重启。
   - 电力接口同时承担输出和输入，不需要额外接一根电线。

7. **发热**
   - 蒸汽发电机自身：4 kW（`SelfHeatKilowattsWhenActive`，对应原版蒸汽涡轮机）。
   - 液体散热器：液体移除的热量 `Q_液体`。
   - 气体散热器：气体移除的热量 `Q_气体`。
   - 总发热 = `4 kW + Q_液体 + Q_气体`，全部加到建筑结构温度上。
   - 因此机器会逐渐升温，达到材料过热温度后停机；需要外部冷却或选择更耐热的材料。

## 数值示例（100% 倍率、满流量）

| 工况 | 总发电 | 散热器耗电 | 净输出 | 电网取电 | 总发热 |
| --- | --- | --- | --- | --- | --- |
| 只接液体（水，10 kg/s，14°C 温差） | 2000 W | 1200 W | 800 W | 0 W | 4 kW + 585 kW |
| 只接气体（氧气，1 kg/s，14°C 温差） | 2000 W | 240 W | 1760 W | 0 W | 4 kW + 14 kW |
| 液体 + 气体同时满负荷 | 4000 W | 1440 W | 2560 W | 0 W | 4 kW + 599 kW |

> 水的 `Q = 10 × 4.179 × 14 ≈ 585 kDTU/s`；氧气 `Q = 1 × 1.005 × 14 ≈ 14 kDTU/s`。
>
> 满流量、满 14°C 温差时，发电与耗电的比例关系如上表，始终有净输出。但如果介质温度已经接近“最低温度”，实际温降会很小：发电按移除热量下降，耗电仍按处理流量计算，就可能出现 `总发电 < 散热器耗电`。此时差额从电网取电；电网无法补足时机器停机。

## 过热行为

- 基础过热温度：75°C。
- 材料提供的过热加成直接生效，例如：
  - 钢：+200°C → **275°C**
  - 铜/铁：+50°C → 125°C
  - 铌：+500°C → 575°C
  - 导热质：+900°C → 975°C
- 达到过热温度后停机，并保留 **10°C 回差**：温度降到 `过热温度 - 10°C` 以下才恢复，避免在临界点反复启停。
- 建筑 `Invincible = true`、`Breakable = false`，过热只会停机，不会损坏。

## DLC 兼容

- `mod_info.yaml` 使用 `supportedContent: ALL`，`requiredDlcIds` 和 `forbiddenDlcIds` 均为空。
- 建筑配置的 `GetRequiredDlcIds` / `GetForbiddenDlcIds` 返回 `null`（表示“无限制”），因此不依赖也不排斥任何 DLC。这里不能返回空数组：`TechItem` 会把非 `null` 数组当成“有 DLC 限制”，研究界面会读取 `requiredDlcIds[Length - 1]`，空数组会触发 `IndexOutOfRangeException`，导致进入世界时研究界面初始化失败。
- 只使用原版基础内容：精炼金属材料、液体/气体管道、电力、`RenewableEnergy` 科技、原版 MultiSlider 侧边栏。
- 原版与 Expansion1 的科技树都包含 `RenewableEnergy`；如果被其他 Mod 改名/重排，会退回到包含 `SteamTurbine2` / `SteamTurbine` 的科技。
- 不包含 DLC 专属元素、建筑或动画资源，也没有针对某个 DLC 的存档/世界生成假设。
- 因此原版、仅启用部分 DLC、以及多个 DLC 混合启用时都可以加载和建造。

- 金属表面叠加拉丝纹理、低频斑驳、细颗粒和随机微划痕，边缘有高光倒角与接触阴影。
- 顶部为铝制散热鳍片与黄铜基座，底部为细密百叶排气格栅，四角、边框和面板上分布螺栓与铆钉。
- 中央为带 24 齿的机械飞轮、六根辐条、轮毂和曲柄销；左右各有一套水平活塞缸、活塞杆和连杆，飞轮通过连杆驱动两侧活塞。
- 面板下方有两个带指针的压力表，左右铜管中有流动的冷却液光点，顶部会冒出淡淡的排气蒸汽。
- 运行时播放 8 帧、10 FPS 的 `working` 循环动画：飞轮旋转、活塞往复、连杆摆动、压力表指针摆动、冷却液流动；停机时播放去饱和、静止的 `off` 状态。

## 构建

环境：macOS + .NET SDK（本机安装在 `~/.dotnet`）。

```bash
./build.sh
```

默认引用本机 Steam 游戏目录：

```
~/Library/Application Support/Steam/steamapps/common/OxygenNotIncluded/OxygenNotIncluded.app/Contents/Resources/Data/Managed
```

如果游戏安装在别处，可覆盖：

```bash
dotnet build -c Release /p:ManagedDir="/path/to/Managed"
```

构建后会自动复制到本地 Mod 目录：

```
~/Library/Application Support/unity.Klei.Oxygen Not Included/mods/Local/ONI-Anti-Entropy-Generator
```

在游戏主菜单的“模组”中启用 **反熵发电机** 即可。

## 说明与设计取舍

- **电力接口只有一个（双向）**：按需求“输入输出 + 电力一共 5 个接口”，同一个电力口既输出净发电量，也在发电不足时从电网取电。这样不需要为散热器单独增加一根输入电线；电网无法补足差额时机器会停机，而不是无电继续冷却。
- **液体/气体各自 2000 W 上限、合计 4000 W**：机器相当于集成了两套独立的热交换通道；这个上限让两种介质同时接入时仍然有收益。
- **发电与移除热量挂钩**：贡献比例使用 `Q / (额定流量 × 比热容 × 14°C)`，因此不同比热容的介质在满流量、满温差下都贡献同样的 2000 W，而低于额定流量或接近最低温度时会按比例降低。
- **热量全部加到建筑自身**：这是“达到材料上限就停机”的前提；玩家可以用输出后的低温介质、外部冷却或其他方式给机器降温。
- **无 DLC 依赖**：`mod_info.yaml` 中的 `requiredDlcIds` 和 `forbiddenDlcIds` 为空，建筑配置的对应方法返回 `null`，原版和 DLC 环境均可加载。
- 按需求没有启动游戏进行实机测试；当前仅完成编译与本地部署。
